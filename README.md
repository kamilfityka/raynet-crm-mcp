# raynet-crm-mcp

Remote MCP server for **RAYNET CRM**. Exposes a small, curated, *read-only*
subset of the RAYNET REST API as MCP tools so Claude (Desktop / Mobile /
claude.ai) can answer CRM questions without touching the raw API.

> **Status:** Full CRUD for Contact database, Business and Activities (no other
> resources). No production OAuth — tenant onboarding is manual via an admin
> endpoint until full OAuth 2.1 + Dynamic Client Registration is wired up.

## Why a thin proxy is wrong here

The RAYNET API has 439 endpoints across 26 resources and exposes destructive
operations (`DELETE`, `merge`, `anonymize`, `bulkDelete`, …). An autogenerated
1:1 wrapper would (a) blow Claude's tool budget, (b) hand the model the keys
to delete data, and (c) leak personal data on every request.

Instead this server is a **business adapter**: a small set of tools that
match how a salesperson actually asks questions, each backed by one or more
controlled RAYNET calls.

```
Claude  ->  raynet-crm-mcp (Streamable HTTP)  ->  RAYNET REST API v2
```

## What's included

The connector covers exactly three areas — **Contact database** (accounts +
contacts), **Business** (deals), and **Activities** (tasks, meetings, calls,
emails, letters, events). Other RAYNET resources (offers, sales orders,
projects, products, price lists, invoices, picklists, GDPR, …) are intentionally
out of scope here.

### Tools

| Tool | Category | Scope | Purpose |
| --- | --- | --- | --- |
| `search_companies` | read | `crm.read` | Search accounts (name / IČO / DIČ / domain). |
| `get_company` | read | `crm.read` | Account profile; mode=`full` adds contacts, open deals, activities, tasks. |
| `create_company` | write | `crm.contacts.write` | Create a new account. |
| `update_company` | write | `crm.contacts.write` | Patch an account (only the fields you pass). |
| `delete_company` | destructive | `crm.destructive` | Delete an account. Requires `confirm=true`. |
| `search_contacts` | read | `crm.read` | Search people. |
| `get_contact` | read | `crm.read` | Person profile; mode=`full` adds deals, activities, tasks. |
| `create_contact` | write | `crm.contacts.write` | Create a new contact. |
| `update_contact` | write | `crm.contacts.write` | Patch a contact. |
| `delete_contact` | destructive | `crm.destructive` | Delete a contact. Requires `confirm=true`. |
| `search_deals` | read | `crm.read` | Search deals (filters: company / person / phase / state / value range). |
| `get_deal` | read | `crm.read` | Deal profile; mode=`full` adds participants, phase changes, activities. |
| `create_deal` | write | `crm.deals.write` | Create a deal; pass `items[]` to use `/createWithItems`. |
| `update_deal` | write | `crm.deals.write` | Patch a deal. |
| `change_deal_phase` | write | `crm.deals.write` | Move a deal to a new phase (separate tool for clearer audit). |
| `delete_deal` | destructive | `crm.destructive` | Delete a deal. Requires `confirm=true`. |
| `list_activities` | read | `crm.read` | Mixed activity feed; filter by type / entity / owner / date / completed. |
| `get_activity` | read | `crm.read` | Single activity by `(type, id)`. |
| `list_upcoming_tasks` | read | `crm.read` | Convenience: open tasks in the next N days. |
| `create_activity` | write | `crm.activities.write` | Create task / meeting / call / email / letter / event. |
| `update_activity` | write | `crm.activities.write` | Patch an activity. |
| `complete_activity` | write | `crm.activities.write` | Mark complete (or reopen); optionally attach a `solution`. |
| `delete_activity` | destructive | `crm.destructive` | Delete an activity. Requires `confirm=true`. |

### Scopes

Scopes are assigned per-tenant at registration time. A tool is exposed only if
the tenant has every scope it requires.

| Scope | Grants |
| --- | --- |
| `crm.read` | All `search_*`, `get_*`, `list_*` tools. |
| `crm.contacts.write` | Create/update of companies and contacts. |
| `crm.deals.write` | Create/update/phase-change of deals. |
| `crm.activities.write` | Create/update/complete of activities. |
| `crm.destructive` | All `delete_*` tools. **Never enabled by default.** |

Recommended starter sets:

- **read-only**: `["crm.read"]`
- **read + write**: `["crm.read", "crm.contacts.write", "crm.deals.write", "crm.activities.write"]`
- **power user**: add `"crm.destructive"` (deletes only).

### Safety properties

- **Stateless Streamable HTTP** transport — no cross-tenant session reuse.
- **Per-tenant concurrency cap** of 3 (RAYNET allows 4). Calls beyond the cap
  queue locally instead of getting a 429 from RAYNET.
- **Never retry on 401.** RAYNET locks the source IP for 60 minutes after 20
  failed logins. Bad credentials surface as `unauthorized` immediately.
- **Rate-limit headers** (`X-Ratelimit-Remaining`/`Reset`) are captured and
  logged; the per-call result records what's left.
- **Pagination capped** at 100 items per call (RAYNET allows 1 000).
- **Destructive tools are gated** behind a separate scope (`crm.destructive`)
  and refuse to run without `confirm: true` in the tool call. Default scope
  for a freshly registered tenant is `["crm.read"]`.
- **Input validation** with Zod on every tool call.
- **Field minimization**: tools project responses down to small, named
  fields rather than passing raw RAYNET payloads through.
- **Credentials at rest** are encrypted with AES-256-GCM if
  `CREDENTIALS_KEY` is set.
- **PII redaction** in logs (auth headers, api keys).

### Multi-tenancy and regions

Each RAYNET deployment lives on a different host (`app.raynet.cz`,
`app.raynetcrm.sk`, `app.raynetcrm.com`, `eu.raynetcrm.com`). A *tenant* in
this server is the tuple `(region, instanceName, username, apiKey)`. Each
tenant gets its own bearer token, its own concurrency budget, and its own
rate-limit window.

## Run it locally

```bash
cp .env.example .env
# edit .env, set ADMIN_TOKENS to a strong random value
npm install
npm run dev
```

Health check:

```bash
curl http://localhost:3000/healthz
```

### Register a tenant

```bash
curl -X POST http://localhost:3000/admin/connect \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "region": "eu",
    "instanceName": "my-crm",
    "username": "user@example.com",
    "apiKey": "RAYNET_API_KEY",
    "label": "Sales team — EU"
  }'
```

Response:

```json
{
  "tenantId": "…",
  "bearer": "rnt_…",
  "mcpEndpoint": "http://localhost:3000/mcp"
}
```

The bearer token is shown **once**. Store it in your MCP client (Claude
Desktop config, custom connector form, etc.).

## Connect from Claude

Until this server is published as a Claude Connector, point a custom MCP
client at:

- **Endpoint:** `${PUBLIC_BASE_URL}/mcp`
- **Transport:** Streamable HTTP (stateless mode)
- **Auth header:** `Authorization: Bearer <token returned by /admin/connect>`

For Claude Desktop, add an entry like this in the MCP servers config (the
exact format depends on your Claude Desktop version):

```jsonc
{
  "mcpServers": {
    "raynet": {
      "url": "https://your-public-host/mcp",
      "headers": { "Authorization": "Bearer rnt_..." }
    }
  }
}
```

## What's deliberately *not* here yet

These are the next milestones, in order:

1. **OAuth 2.1 + Dynamic Client Registration** so claude.ai can onboard
   tenants directly without an admin step.
2. **Idempotency-key-aware writes** + a persistent audit log for every
   `create_*` / `update_*` / `change_*` / `delete_*` call. Writes are live
   today, but Claude retries can produce duplicates.
3. **Short-TTL response cache** (15–60 s) for `companies/{id}`, picklist
   reads, and phase lookups, to avoid burning RAYNET's 24 000/day budget on
   repeat reads.
4. **Persistent rate-limit token bucket per tenant** in Redis (current
   implementation is in-process; it will not be correct across multiple
   replicas).
5. **Discovery tools for picklists** (`list_deal_phases`, `list_categories`,
   `list_users`) so Claude can fetch ids it needs for reference fields.

Out of scope for this connector: offers, sales orders, projects, products,
price lists, invoices, GDPR templates, mass email, webhook configuration,
custom field schema editing.

## Project layout

```
src/
  client/raynet.ts       RAYNET REST client (auth, concurrency, rate-limit, errors,
                         GET/list/PUT/POST/DELETE helpers).
  tools/shared.ts        Shared Zod helpers, refOf/clean, response minimizers.
  tools/companies.ts     Contact database — accounts.
  tools/contacts.ts      Contact database — people.
  tools/deals.ts         Business — deals (incl. participants, phaseChanges).
  tools/activities.ts    Activities — task/meeting/call/email/letter/event.
  tools/index.ts         Tool registry + scope filtering.
  mcp/server.ts          MCP server bound to a tenant + Streamable HTTP transport.
  auth/store.ts          File-backed (optionally encrypted) tenant credentials.
  auth/middleware.ts     Bearer + admin auth for Express.
  util/{config,errors,logger}.ts  Shared infra.
  index.ts               Express bootstrap, /admin/* and /mcp.
```

The OpenAPI spec lives at `documentation/api/openapi.json` and is the source
of truth for endpoint paths and filter names.

## Operational notes

- RAYNET's 24 000/day limit is per **instance**, not per integration. Your
  human users share that budget with this server. Running `get_company_context`
  spends 5 calls (1 detail + 4 parallel sub-queries).
- Mind the 4-concurrent-connection limit: this server already self-throttles
  to 3, but if you run multiple replicas you will need a shared limiter.
- Revoke a bearer with `DELETE /admin/tenants/<id>` (admin token required).
